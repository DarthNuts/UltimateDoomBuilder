# ZT: инструменты форка UDB для Zero Tolerance

Форк Ultimate Doom Builder под проект Zero Tolerance: https://github.com/DarthNuts/UltimateDoomBuilder
(`upstream` — UltimateDoomBuilder/UltimateDoomBuilder). Планы — [workbench-plan.md](workbench-plan.md) (весь
инструмент, этапы и решения) и [mcp-plan.md](mcp-plan.md) (MCP-сервер в UDB).

## Ветки форка

| Ветка | Что в ней |
|---|---|
| `zt/script-encoding` | UTF-8 в редакторе скриптов: кодировка по умолчанию, автоопределение, перекодировка Windows-1251 ↔ UTF-8 |
| `zt/workbench` | от `zt/script-encoding`: планы, плагин ZTProject, утилита ZTMapMerge (этап 2) |

Подтянуть upstream: `git fetch upstream` и слить `upstream/master` в нужную ветку `zt/*`.

## Сборка и запуск

- `.\zt-build.ps1` в корне форка — без Visual Studio (MSBuild 17 из SSMS 21 + Roslyn из .NET SDK). Собирает ядро,
  все плагины и `Build\Tools\ZTMapMerge`, складывает zip в `GIT_Build\`. **UDB при сборке должен быть закрыт**:
  открытый UDB держит DLL, а сборка ядра чистит `Build\`.
- `.\zt-build.ps1 -Plugin ZTProject` — пересобрать только плагин (ядро уже в `Build\`), меньше минуты.
- Запуск — `Build\Builder.exe`. Без `-portable` он берёт общие настройки с установленным UDB (ресурсы Zero Tolerance
  там уже настроены).

## Плагин ZTProject: карта прямо из рабочей копии и две кнопки

Нужна рабочая копия проекта на ПК — клон голого репозитория ИИ-машины (один раз):
```
git clone -c core.autocrlf=false -c core.sshCommand="ssh -i C:/Users/Ser/.ssh/zt_vm -o BatchMode=yes" dev@<IP>:/srv/git/ZeroTolerance.git C:\Users\Ser\source\repos\ZeroTolerance
git -C C:\Users\Ser\source\repos\ZeroTolerance switch dev
```

В UDB:
1. **ZT → «Папка проекта…»** — корень клона (папка, где лежит `wad-src\wad_structure.json`). Запоминается.
2. **ZT → «Открыть карту проекта…»** — список карт из `wad_structure.json`. Карта собирается из `wad-src\<КАРТА>\` во
   временный WAD `%LOCALAPPDATA%\ZTWorkbench\<проект>\<КАРТА>.wad` и открывается. Первый раз UDB спросит параметры
   карты (игровая конфигурация и ресурсы — как для `ZeroTolerance.wad`); они запоминаются в `.dbs` рядом с временным WAD.
3. **Сохранение (Ctrl+S)** раскладывает лампы карты обратно в файлы: `TEXTMAP`, `SCRIPTS.acs`, `BEHAVIOR.lmp`,
   `DIALOGUE.lmp`. Пишутся только изменившиеся.
4. **«Отправить»** (кнопка на панели или меню ZT): сохранить, показать список изменений и поле комментария,
   закоммитить всё (сообщение собирается само: карты по лампам, остальное по папкам) и отправить текущую ветку. Если на
   сервере уже есть новое — сначала «Получить».
5. **«Получить»**: сохранить, неотправленное закоммитить локально (оно не теряется), слить свою ветку с сервера. Если
   изменилась открытая карта — она перечитывается **на месте одним шагом отмены**: вид, режим и выделение остаются,
   Ctrl+Z возвращает карту как до получения. Скрипты (`SCRIPTS`, `BEHAVIOR`, `DIALOGUE`) заменяются во временном WAD,
   вкладка скрипта перечитывается. Если на месте не вышло (причина — в отчёте и в `UDBuilder.log`), карта
   открывается заново, как раньше.
6. **Ветка** рабочей копии видна в строке состояния, после названия игровой конфигурации.
7. **ZT → «Получить сборку»** — машина собирает WAD и pk3 своей ветки с сервера в отдельной копии `~/ci/ZeroTolerance`
   (рабочую копию, где работает Claude, сборка не трогает; результат — `~/ci/out/<ветка>/`, тот же коммит повторно не
   собирается), плагин скачивает изменившиеся файлы в папку GZDoom (сверка sha256, запись через `.part`) и перечитывает
   ресурсы UDB. Идёт в фоне, ход — в строке состояния. Папка GZDoom — папка `ZeroTolerance.pk3` из ресурсов игровой
   конфигурации (или выбор, запоминается). Сборка pk3 в моде повторяема (`build.py`): одинаковый `src/` — одинаковый
   pk3 байт в байт, поэтому неизменившийся файл не качается.
8. **Ресурсы из `src/`** (ZT → «Ресурсы из src/ (без сборки pk3)», по умолчанию включено): у карт проекта ресурс —
   папка `src/` рабочей копии вместо собранного `ZeroTolerance.pk3` (он не грузится, иначе классы, cvar и звуки
   определены дважды): новые текстуры, спрайты и акторы видны в UDB без сборки и скачивания pk3. Тест карты в игре
   по-прежнему получает pk3. Файлы `src/` поменяли вне UDB или пришли через «Получить» — ресурсы перечитываются,
   карта и история отмены остаются. Если параметры карты уже есть (`.dbs`), «Открыть карту проекта» открывает её
   сразу, без окна параметров.
9. **ZT → «Открыть файл проекта…»** — файл рабочей копии (ZScript, DECORATE, MAPINFO, SNDINFO…) во вкладке редактора
   скриптов UDB, подсветка по типу файла. При сохранении хвостовые пробелы не срезаются (иначе шум в git: они есть
   в 39 файлах мода); если файл поменяли снаружи (например, «Получить»), сохранение спрашивает, а не затирает.
   Вкладки без несохранённых правок перечитываются, когда файлы `src/` меняются снаружи или приходят через «Получить».
   Сохранили файл `src/` — ресурсы UDB перечитываются (слежение).
10. **ZT → «Проверить скрипты мода (GZDoom)»** — GZDoom из папки игры грузит мод в порядке `ZeroTolerance.bat`, но с
    `src/` рабочей копии вместо собранного pk3, с `-norun` (~6 с без ошибок; ini игры не трогается — временная копия).
    Ошибки ZScript/DECORATE («Script error … line N») — в списке ошибок редактора скриптов, файл открывается во
    вкладке, клик — строка. GZDoom запускается под скрытой консолью cmd: без консоли у родителя он открывает свою и
    после `-norun` ждёт «Press any key».
11. **ZT → «Тест карты в игре (порядок мода, src/)»** — карта из UDB (со скомпилированными скриптами) во временный WAD,
    GZDoom в порядке `ZeroTolerance.bat`, `src/` вместо собранного pk3, тестовый WAD последним, `+map <карта>`: правки
    `src/` проверяются в игре без сборки. Ошибки компиляции ACS — в редакторе скриптов, игра не запускается. Встроенный
    Test Map UDB (F9) остаётся с ресурсами игровой конфигурации.
12. **Слежение за файлами.** Файлы открытой карты (`wad-src/<КАРТА>/`) поменяли вне UDB — git в терминале, скрипт
   мода, правка руками: через секунду тишины карта перечитывается на месте одним шагом отмены. Если в UDB есть
   несохранённые правки — вопрос: «Да» — взять файлы (правки вернёт Ctrl+Z), «Нет» — оставить правки (при сохранении
   они перезапишут файлы). Свои записи плагина (сохранение, «Получить», «Отправить») не в счёт — сверяется отпечаток
   файлов. Во время модального окна или действия в карте (перетаскивание) перечитывание ждёт.
   То же вручную — ZT → «Перечитать карту из файлов».

Как перечитывается на месте (`MapReload.cs`): новая версия TEXTMAP читается в отдельный `MapSet`, элементы
сопоставляются с картой тем же `UdmfMerger.Correspond`, что у ZTMapMerge, и в карту переносится только разница —
поля, добавленные и удалённые элементы, затем порядок элементов, как в файле (иначе следующее сохранение
перенумеровало бы карту). Итог проверяется: карта, записанная из памяти, совпадает байт в байт с файлом, прочитанным
UDB. Для этого в ядре форка — `Source/Core/ZT/ZTMapTools.cs` (чтение и запись UDMF, внешняя правка одним шагом
отмены) и перестановка сторон линий с записью в историю отмены (`Sidedef.ChangeIndex`).

Карты сливаются семантически (ниже). Если одно поле карты изменено по-разному с двух сторон, «Получить» открывает
**окно конфликтов карты** (`MapConflicts.cs`): по каждому полю — база, «у нас», «у них»; «Показать на карте»
выделяет элемент и показывает его; «Взять «у них»» / «Всё «у них»». «Завершить слияние» записывает выбор в TEXTMAP,
коммитит слияние (в сообщении — итог выбора) и перечитывает карту на месте одним шагом отмены; «Отменить слияние»
возвращает всё как до «Получить». Элемент, удалённый с одной стороны и изменённый с другой, остаётся (удалить — в
UDB). Конфликт в других файлах (скрипты, `src/`) по-прежнему отменяет слияние — ваши правки в локальном коммите.

Ограничения пробной версии: дерева ресурсов в редакторе скриптов нет (файл — через «Открыть файл проекта…»).

## MCP-сервер: UDB для агента

В плагине ZTProject — MCP-сервер ([mcp-plan.md](mcp-plan.md)): агент (Claude Code и др.) читает открытую карту,
показывает элементы, управляет окнами UDB и действиями плагина. Так агент сам проверяет работу UDB без ручных тестов.
- **Включить:** ZT → «MCP-сервер» → «Только чтение» или «Чтение и правка» (запоминается; по умолчанию выключен).
  Переменная окружения `ZT_MCP=rw` (`ro`, `off`) при запуске UDB заменяет настройку — так агент запускает UDB сам.
- **Адрес** `http://127.0.0.1:47390/mcp` (Streamable HTTP, JSON-RPC 2.0), только этот ПК, токен в заголовке
  `Authorization: Bearer`. Адрес и токен — в `%LOCALAPPDATA%\ZTWorkbench\mcp.json`, пока сервер работает.
- **Подключить Claude Code:** ZT → «MCP-сервер» → «Скопировать подключение для Claude Code» и выполнить команду
  (`claude mcp add --transport http udb … --header "Authorization: Bearer …"`).
- **Инструменты:** `map_info`, `get_elements`, `query_elements`, `get_selection`, `select` (карта — как в TEXTMAP);
  `set_fields` — поля TEXTMAP у элементов по номерам (с `expect_revision`) или по условию, одним шагом отмены;
  `udmf_schema` — порядок полей, как их пишет UDB (для скриптов, которые пишут TEXTMAP);
  `config_catalog` — спецы, эффекты секторов, типы вещей (с акторами мода), флаги, UDMF-поля; `scripts_list`,
  `script_read`, `scripts_compile` — скрипты карты и компиляция ACS с ошибками; `map_analysis` — Map Analysis UDB;
  `zt_get_build` — «Получить сборку»; `editor_open_file`, `editor_tabs`, `editor_text` — вкладки редактора скриптов
  (открыть файл проекта, прочитать и заменить текст, сохранить); `zt_check_scripts` — проверка скриптов мода в GZDoom; `zt_test_map` — тест карты в игре; `render_2d` — схема области карты в PNG с подсветкой и номерами (вид в UDB не
  меняется);
  `ui_windows`, `ui_click`, `ui_select_rows`, `ui_set_text`, `screenshot` (окна UDB и MessageBox); `run_action`
  (действия UDB и плагина, например `ztproject_ztget` — «Получить»), `undo`/`redo`; `zt_set_project`, `zt_open_map`
  (без окна параметров — по `.dbs`), `zt_reload_map`. Правки и действия — только в режиме «Чтение и правка».
- Действие, открывшее модальное окно (окно конфликтов, MessageBox), продолжается в UDB: `run_action` возвращает
  список окон, дальше — `ui_windows` и `ui_click`.
- Код: `Source/Plugins/ZTProject/Mcp/` (HTTP — свой, поверх TcpListener: HttpListener требует резервирования адреса).

## ZTMapMerge: семантическое слияние карт

`Source\Tools\ZTMapMerge` — утилита для git и для ручного запуска. Элементы карты сопоставляются по смыслу, а не по
номерам строк:
- вершины — по координатам;
- линии — по координатам концов;
- стороны — через свои линии;
- секторы — по большинству своих сторон;
- вещи — по содержимому, затем по типу и месту, по типу и id.

Поле, изменённое с одной стороны, берётся; изменённое по-разному — конфликт. Ссылки перенумеровываются. Удаление
вершин с одной стороны не сдвигает правки другой стороны на чужие линии — построчный git на таком случае ошибается
молча.

```
dotnet Build\Tools\ZTMapMerge\ZTMapMerge.dll merge <база> <наша> <их> [<результат>]   # код 1 — есть конфликты
dotnet Build\Tools\ZTMapMerge\ZTMapMerge.dll summary <старая> <новая>                  # что изменилось (как видит UDB)
dotnet Build\Tools\ZTMapMerge\ZTMapMerge.dll roundtrip <файл>…                          # запись совпадает байт в байт
```

Драйвер git: в `.gitattributes` проекта у карт, которые правят в UDB, стоит `merge=udmf`.
- На ПК плагин сам прописывает в клон `merge.udmf.driver = dotnet "<UDB>/Tools/ZTMapMerge/ZTMapMerge.dll" merge %O %A %B`.
- На ИИ-машине — `/opt/zt/ztmapmerge` и `/etc/gitconfig` (нужен `dotnet-runtime-10.0`).
- Без настроенного драйвера git сливает эти файлы построчно.

Файлы `Udmf\*.cs` написаны под C# 7.3 без зависимостей — их же подключит плагин (.NET Framework 4.7.2) для окна
конфликтов. Утилита — `net10.0`, собирается `dotnet build` без NuGet.
